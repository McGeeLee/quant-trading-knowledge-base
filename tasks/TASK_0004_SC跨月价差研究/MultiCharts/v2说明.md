# v2 连续上涨做多价差信号

用户于 2026-09-09 确认方向：价差连续上涨后，多 SC2610、空 SC2611。本版本为双图日线历史回测 Signal；保留 v1 观察指标。

## 规则与参数

- 价差始终为近月减远月。UpDays=3 表示连续三个日变化为正，需要四个日收盘值，例如 10→11→12→13。相等或下降会清零。
- 第三次上涨的日线收盘确认，下一交易日两腿各按日开盘价模拟成交。不是信号日收盘成交。
- 入场组合价差为入场日近月 Open−远月 Open。SP=5 表示价差比入场扩大至少 5 元/桶；SL=3 表示比入场收窄至少 3 元/桶。
- 在每个日收盘（包括入场日）检查，满足任一条件后，下一交易日开盘两腿退出。日内触及又回落不触发；跳空或日内大波动会使实际亏损超过 SL，SL 不是亏损上限。
- Lots=1 为两腿各一手。持仓期间不加仓；平仓日不重入，从平仓日收盘作为新基准，再累计完整的 UpDays 次上涨。
- 默认 3/5/3/1 为演示参数，未经优化，不代表盈利参数。SP/SL 是价差点数，不是单腿点数、百分比或人民币金额；不含手续费和滑点。

## 为什么需要两张图

MC 普通图表 Signal 的订单针对 Data1。一个图中写 Buy 和 SellShort 不会分别交易 Data1 和 Data2，可能只是对同一合约反手。故用同一份代码的两个实例，在两张日线图中互换数据顺序：

| 设置 | 图 A：近月腿 | 图 B：远月腿 |
|---|---|---|
| Data1 | SC2610 | SC2611 |
| Data2 | SC2611 | SC2610 |
| NearIsData1 | True | False |
| 下单方向 | 买入近月，卖出平仓 | 卖空远月，买入平仓 |
| UpDays / SP / SL / Lots | 3 / 5 / 3 / 1 | 完全一致 |
| 两个序列周期 | 都为 1 日 | 都为 1 日 |

两图使用相同 Session、时区、起止日期、最大引用 K 棒数量和相同完整数据。设置最大引用 K 棒数量为同一个固定值（例如 1；脚本仅引用上一根，其余状态逐日累计）。不要直接把本信号加到现有一分钟观察图上，“3 天”不是“3 根一分钟 K 线”。另开两个历史研究图，原观察图可保留。

这两个实例按相同历史价格独立重现同一组合决策，不是实时订单协调器。不会检查另一张图的经纪商成交，也不能保证两腿同时成交。为避免这种模型用于实盘，代码在自动交易启用或实时计算时抛出错误；该检查不替代平台设置，装载前仍须关闭自动交易。使用已经结束的历史日期范围。

## 安装

1. PowerLanguage Editor → 新建 → Signal，命名 `SC_Spread_UpDays_v2`。
2. 粘贴 [完整源码](v2_连续上涨做多价差信号.txt)，F3 编译。
3. 两张日线图各加入同一个 Signal，按上表设定 NearIsData1。
4. 每图只装这一个交易信号，允许相应方向、各一手，不加仓，关闭 IOG、自动交易。脚本显式禁用 IOG。
5. 核对两图输出中的 PAIR_ENTRY_SIGNAL、PAIR_ENTRY、PAIR_TP_SIGNAL / PAIR_SL_SIGNAL：日期和组合价差应相同，订单方向相反。若日期不一致或任一图报错，两份结果不能合并。
6. 双腿交易清单按入场、出场日期逐笔对齐，合并盈亏并扣两边费用。单图报告只是单腿收益，不能当组合收益；最大回撤要先合并同一时刻净值再计算，不能直接相加两图最大回撤。

日线两腿各自的 Open 未必能同时成交。SP/SL 的触发使用这两个历史 Open 的价差；MC 设置的滑点会改变单腿报告收益，但不会改变此理想化触发基准。真实成交价、盘口、拒单、部分成交、断连、双腿对账应在后续执行版处理。

## 验收用例

以 UpDays=3、SP=5、SL=3 为例：

| 场景 | 预期 |
|---|---|
| 日收盘价差 10、11、12、13 | 第四日收盘发信号，第五日开仓 |
| 第五日开盘价差 15，当日收盘 20 | 入场基准 15，日收盘触发止盈，第六日开盘平仓 |
| 第五日开盘价差 15，当日收盘 12 | 日收盘触发止损，第六日开盘平仓 |
| 上述止损后第六日开盘价差 9 | 实际毛损失 6 点，而非 3 点 |
| 日收盘价差 10、11、11、12 | 中途持平中断连续上涨，尚不入场 |
| 持仓期间价差继续上涨 | 不重复加仓 |
| 交换数据顺序并将 NearIsData1 改 False | 同日期进出，交易方向变为空远月 |

源码经静态检查；配套 Python 参考状态机用合成行情验证入场时点、止盈止损、跳空、重入和双腿盈亏恒等式。Python 测试不能代替 MC 编译及其撮合引擎验证。目标 MC 的 F3 编译与双图交易清单比对尚未完成，未进行实盘运行。

回测结束可能留有未平仓或下一根待执行订单，必须单独标记；不要假设末尾自动平仓。到期退出尚未自动化，研究日期须截在合约到期前，至少保留一根出场 K 线；本版本不能用于持仓进入交割。
